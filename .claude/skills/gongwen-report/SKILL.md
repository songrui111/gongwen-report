# 公文 / 行业分析报告

这个仓库里有一套**已经成型的规范**和一台**检查器**。两件事都别自己重新发明：

- 规范在 `gongwen/templates/` 里，但不直接读模板 —— 用 `--print-system` 把**装好的**
  那一份取出来（主题、主送机关、参考资料都填进去了，就是送给模型的那一份原文）。
- 检查器是 `report_check.py`。**写完必须跑**，报红的逐条改到全绿再交。

## 步骤

### 1. 取规范

```bash
py report_check.py --print-system --topic "<报告主题>" --to "<主送机关>" > system.md
```

- `--topic` 必给（行业/领域，≤200 字）。
- `--to` 是主送机关的全称或规范化简称（如「某某市科学技术局」）。**给了就逐字照抄，
  不许简写成「市科技局」**；不确定就不给 —— 没给的话这一行整行不写，别自己编一个机关名。
- `--desc` 是补充说明（比如「重点写政策工具」）。
- `--docs <file>` 传一份要**照着它的体例**写的范本；`--refs <file>` 传参考资料。
  **这两个是它唯一的资料来源 —— 它不会自己去联网查。** 没有资料就明确说「给我资料」，
  不要凭印象编数据。
- 正文打到 stdout、`fmt: gw|exemplar` 这行打到 stderr。要看骨架选了哪一套就看 stderr。

`system.md` 就是规范全文，**照它写**。

### 2. 照规范写

把 `system.md` 当唯一的体裁依据。几条最容易踩的：

- 正文是**段落**，不是项目符号；不要加粗、不要 emoji、不要「综上所述」这类作文腔。
- 层次序数：一级「一、二、三、」，二级「（一）（二）」。各级一律顶格（不缩进）。
- 表格至少两张，表号表题写在表格**上方**，需要单位就另起一行「（单位：亿元）」。
- 字数 8000–16000。**同一句话不要在不同章节反复出现**（≥24 字的片段出现 3 次就报红）。
- 落款是发文机关署名 + 成文日期两行，不写「以上报告，请审阅」这类自我免责段。
- 数据、政策文件名、书名号里的东西**只能是参考资料里有的**。核不到就不要写 ——
  检查器会把对不上的书名号列出来。

### 3. 落盘成 Markdown

标题用 `#`，正文照常写。文件名随意，`<名字>_refs.md` 放在旁边（参考资料原文），
检查时会自动读它来核书名号。

### 4. 检查

```bash
py report_check.py 报告.md
```

退出码：`0` 全过 / `1` 有失败项 / `2` 用法或环境问题（**2 不等于通过**）。

**`FAIL` 开头的行是必须改的**，每条后面跟着实际量到的数，照着改。
结尾「机器判不了的，列出来给人看」那一节不参与打分，但要看一眼：书名号核不上的、
位次表述「第 X 位」没有出处的，都得回去改或补资料。

### 5. 改到全绿再交

判据**一条都不许放宽**：不许改 `gongwen/rules.py` 的阈值、不许删规则、不许给判据加
例外来让某一份报告变绿。报红是有原因的，改报告，不是改尺子。

## 生成（可选，要密钥）

```bash
py report_check.py --gen --topic "<主题>" --to "<主送机关>"
```

会真的调模型、真的花钱。没配密钥时会明确报错退出并把上面那条零密钥的路列在前面。
默认落在 `out/report_after.md`。**这条路和上面那条是同一套规范**，产物跑完检查器
也是同一个。拿不准就用零密钥那条。

## 别做的事

- 不要为了过检把段落拆成短句、把表格数据删掉 —— 那些数字正是报告要说的东西。
- 不要在没有参考资料时凭印象写政策文件名、文号、统计数据。核不上就是编的。
- 不要把范本（`--docs`）的内容抄进报告：范本给的是**体例**。报告和范本逐字重合 ≥24 字的
  片段会被列出来。
