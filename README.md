# gongwen-report

**给「公文 / 行业分析报告」打分和生成的一套规矩，零第三方依赖、零密钥就能跑。**

十六七条判据不是拍脑袋来的，是照着 GB/T 9704—2012 起出来、再被真实报告一份一份撞出来的：
正文得是段落不是项目符号、层次序数怎么排、主送机关顶格、落款按 7.3.5.2 右空二字、
表格和正文统一 3 号字、全文 8000–16000 字……每一条都能说清它拦的是什么。

```bash
py report_check.py --selftest          # 不需要装任何东西，不需要联网，不需要密钥
```

---

## 30 秒看见它报红

```bash
py report_check.py fixtures/golden_gw.md                    # 全绿样本 → 全部通过，退出码 0

py fixtures/derive.py                                       # 从全绿样本派生三个「只差一处」的坏样本
py report_check.py fixtures/_derived/broken_repeat.md       # → 失败 1 项，退出码 1
```

第三行会打出这样一行 —— 十六格里**只有它**红：

```
FAIL 没有整句重复（≥24 字的片段不得出现 3 次）  1 处，最多的一段重复 3 次：。 2025年某市低空经济全产业链产值412.6亿元，比20…
```

**「只红该红的那一条」是这套东西里最要紧的性质。** 一份有毛病的报告，如果连带十条不相干的
判据一起报红，那就没人会去看那份报告了。所以每个坏样本都是现派生的、每次只改一处，
派生完立刻核对「确实只报出那一条」（`fixtures/derive.py` 自己就带这一步）。

## 规矩清单

```
$ py report_check.py --list-rules
公文专属  开篇有「摘要」章（照范本格式时跳过）
公文专属  有「数据来源」章且非空（照范本格式时跳过）
公文专属  一级标题用「一、二、三、」（照范本格式时跳过）
公文专属  二级标题用「（一）（二）」且不止一个（照范本格式时跳过）
通用      正文是段落（≥25 段）
通用      不用「-」项目符号（≤3 行）
通用      正文没有加粗
通用      没有 emoji
公文专属  至少有 2 张表格（照范本格式时跳过）
通用      不引用「图 N」（本报告没有配图）
公文专属  建议用「一是……二是……三是……」（照范本格式时跳过）
公文专属  有归类归纳（「划分为三类：……分别为……」）（照范本格式时跳过）
通用      没有「综上所述」这类作文腔
通用      没有自我免责段（面板底部已有提醒）
公文专属  正文 8000-16000 字（照范本格式时跳过）
通用      没有整句重复（≥24 字的片段不得出现 3 次）
```

这一屏**不是文档抄的，是 `rules.RULES` 这张表渲染出来的**。规则名、是不是「公文专属」
（决定 `--exemplar` 时跳不跳）、清单本身，三者同一处定义。上一版是三份平行的字符串清单，
改一个字 skip 就静默失效 —— 表现是照范本写时满屏假红，而且没人知道为什么。

每条判据后面跟着**实际量到的数**（`51 段`、`9814 字`、`2 张表，表号 3 处`），不是一句
「通过」。判据判的是什么，看输出就知道，不用翻代码。

最后那一节是**机器判不了、列出来给人看的**：位次表述「第 X 位」有没有出处、归类归纳出现
在哪、参考资料里哪些书名号对不上。**这一节不参与打分，也不拦退出码** —— 把「机器判不了」
硬凑成一个布尔值，比不判更坏。

## 两条入口

### 一、零密钥：`--print-system`

检查这一半完全不需要模型。要生成，也不必给它配密钥：

```bash
py report_check.py --print-system --topic "某市低空经济产业" --to "某某市科学技术局" > system.md
```

把 `system.md` 交给任何一个能写字的模型（Claude Code 里就是本仓库自带的 Skill），照它写；
写完了拿回来检查：

```bash
py report_check.py 报告.md
```

`--print-system` 打到 stdout、`fmt: gw|exemplar` 这行打到 stderr，所以重定向出来的是干净
的一份规范。**这条路永远可用**，也是这条工具实际被推荐的用法。

旁边放一份 `<同名>_refs.md`（参考资料），检查时会自动读 —— 书名号里的文件名是不是编的，
就靠它核。生成的时候会自动落一份。

### 二、直连生成（可选）：`--gen`

```bash
export DEEPSEEK_API_KEY=...             # 或者 cp .env.example .env 再填
py report_check.py --gen --topic "某市低空经济产业" --to "某某市科学技术局"
```

OpenAI 兼容接口，DeepSeek / 硅基流动 / 本地 Ollama 都能接（`DEEPSEEK_BASE_URL` 指过去即可）。
这条路会真的调模型、真的花钱，所以**没配密钥时它明确报错退出**（退出码 2），并把零密钥那条
列在前面。

**没配密钥时不会发起任何请求** —— 不是「发出去等 401」。上游出错、连不上、被中断，
一律**不落盘**：一份半截报告比没有报告更误导人。密钥一律从环境变量读，**不留任何默认值**。

## 和「应用里的那个功能」相比，生成这件事变了什么

这一版是从一个完整应用里剪出来的，剪的时候有意去掉了一半：

- **不再自主联网检索。** 参考资料由 `--refs <file>` 或 `--docs <file>` 传进来，检索那
  一半（向量库、网页搜索、白名单）整段剪掉了。好处是这一半变成纯函数、可复现、不需要
  任何外部服务；代价是**它不会自己去查了**，得你把资料给它。这是有意的取舍，不是漏搬。
- **骨架只有一套。** 命中「按上传文档的格式写」而且真从文档里抽出了骨架，才换成范本骨架；
  抽不出骨架（传的是 xlsx 导出的表格、通篇没有编号标题）就退回公文骨架。
  「命中了但抽不出东西」不能交出一份没有骨架的报告 —— 那是这个功能唯一比默认行为更糟的结果。
- **范本身份要守住。** 上传的范本是**素材**，不是内容模板。报告和范本逐字重合 ≥24 字的片段
  会被列出来（`--docs` 时自动打），对策句的着力点重合不算抄，整句照搬才算。

## 证伪这件事本身

一个只会说「通过」的检查工具，没人信。所以每一层都有**把自己改坏**的入口：

```bash
py report_check.py --selftest            # 36 项：判据本身在不在判、规则表是不是唯一来源
py fixtures/derive.py                    # 三个「只差一处」的坏样本，逐份核对只报出那一条
py tests/test_print.py                   # 五种版式改坏，每种必须由**指定那一条**报红
py tests/run_all.py                      # 一次跑完全部
```

版式那一层尤其较真：它开一个 headless 浏览器**量真页面**，再印一份 PDF **回读字号和边距**。

| `--break` | 改坏的是 | 谁该报红 |
|---|---|---|
| `indent` | 缩进按元素自身字号算（不是正文字号） | 层次序数同起排（只在屏幕上看得见） |
| `sign` | 落款日期不与署名右移二字 | 落款右空（标准 7.3.5.2） |
| `font` | 落款拿不到正文字号、掉回默认字族 | 落款字号与正文一致（同一次里「落款是仿宋」也红） |
| `table` | 表格掉回四号 | 正文与表格统一 3 号（只在纸面上看得见） |
| `paper` | `@page` 四边边距错 | 版心边距（只在纸面上看得见） |

**「必须是指定那一条报红」—— 只判「有红」不够。** 改坏了缩进却让「落款字号」报红，
说明这两条判据接错了线，那种红没有任何意义。

想自己看一眼版式（人看的那条路，和上面是同一份渲染）：

```bash
py preview/build.py fixtures/golden_gw.md --png 版式.png     # 截一张
py preview/build.py fixtures/golden_gw.md --png 坏的.png --break indent   # 故意改坏，对着看
py preview/build.py --print-frontier                        # 这台机器上找不找得到 Edge
```

Markdown 渲染用 `marked`，安全过滤用 `DOMPurify`，两个库**离线 vendored** 在
`preview/vendor/`（出处和许可见那里的 `NOTICE.md`），不走 CDN。

### 三个退出码，`2` 和 `1` 分开

```
0   全过
1   有失败项 —— 报告有毛病，去改报告
2   用法错，或环境缺东西（含 --gen 没配密钥）
```

**「我没跑起来」不能混进「报告不合格」。** 脚本里靠退出码判断「这份报告能不能交」的时候，
少了 Edge、少了 pypdf，都必须响亮地说「这一层没验」，而不是安静地变绿 —— 那种绿过一阵子
就没人再信了。所以测试里凡是环境缺失，一律打印「没验 N 项（≠ 通过）」并给退出码 2。

包内还有一层纯逻辑自检跑在只装了标准库的机器上：**`--selftest` 不 import 任何第三方库，
不联网，不读密钥**。剪出来的东西是不是真的独立，这件事本身是被跑出来的，不是写在文档里的。

## 已知边界（知道而不改的，写在这儿）

判据是从实战里抄下来的，所以有几处**故意**不认：

- **「照着我上传的报告的格式写」不认。** 认的是「这篇文章 / 这份文档 / 这个附件」那一组
  指代；「上传的报告」不在里面。判不准就不认（fail-closed）—— 漏判只是退回公文格式，
  误判会把别人的骨架套到一份公文上，后者糟得多。
- **「以附件为准」不认。** 说的是什么「为准」？可能指数据，也可能指格式。判不准就不认。
- **否定词隔了 9 个字以上，闸门仍会开。** 比如「按照我上传文档的格式写，但那份文档只是
  素材」—— 这里想说「只是素材、别照抄」，闸门却认了格式。这是原判据的窗口宽度（往回看
  8 个字）的直接后果，属于**已知**边界，不是意外。
- **带上传标记时，体例提示里的「结尾有」不列。** 拼接用的分隔行挤掉了尾部四分之一，
  于是「参考文献」这种结尾体例看不到。**骨架里仍然有那一行**，换骨架不受影响，少的是
  提示里的一句锦上添花。
- **上传 `.md` 抽不出体例。** 抽取认的是 PDF/Word 抠出来的**裸标题**（一行一个「一、引言」），
  Markdown 的 `## 一、引言` 一行都认不出来。要它认，把上传的文档存成 docx/pdf。
- **`--gen` 不再自主联网**（见上）。

## 仓库里没有什么

- **没有任何密钥**，也没有默认值。`test_no_secrets.py` 每次都扫一遍全仓，扫描器自带对照
  组（真扫不到东西时会红，不会静默变绿）。
- **没有真实生成的报告。** `fixtures/` 里的样本是照规范写的中性抽象样本，无地域、无单位、
  数据是演示用的。真实报告只在本机做过交叉验证，不进版本库。
- **没有 PPT、没有向量库、没有国标 PDF、没有单位资料。**

## 出处与许可

规则清单、版面参数、判据阈值全部来自 GB/T 9704—2012《党政机关公文格式》以及在真实报告上
一轮一轮跑出来的结果。**判据是搬过来的，不是重新设计的** —— 阈值一个都没放宽，搬迁的验收
标准是「同一份报告在新旧两边逐条给出同样的结论」。
