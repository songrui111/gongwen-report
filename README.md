# gongwen-report

给公文和行业分析报告打分、生成的一套规矩，附一个 Claude Skill。零第三方依赖、零密钥就能跑。

![版式预览](docs/preview.png)

上面这一页是 `fixtures/print_sample.md` 排出来的。最上面是版头（份号、密级、紧急程度、红色「发文机关标志」、发文字号、签发人、红色分隔线），往下是居中标题、顶格的主送机关、一律顶格的四级层次序数、统一 3 号字的表格、写在表格上方的表号表题，结尾是右空二字的落款和版记——这些都是判据在量的东西，不是画出来的。版头/版记和落款一样由参数给，见下面「版头、版记和落款」一节。

十六七条判据照着 GB/T 9704—2012 起出来，每条都能说清它拦的是什么：正文得是段落不是项目符号、层次序数怎么排、主送机关顶格、落款按 7.3.5.2 右空二字、表格和正文统一 3 号字、全文 8000–16000 字。

```bash
py report_check.py --selftest          # 不需要装任何东西，不需要联网，不需要密钥
```

## 30 秒看见它报红

```bash
py report_check.py fixtures/golden_gw.md                    # 全绿样本，退出码 0

py fixtures/derive.py                                       # 派生三个「只差一处」的坏样本
py report_check.py fixtures/_derived/broken_repeat.md       # 失败 1 项，退出码 1
```

第三行会打出这样一行，十六格里只有它红：

```
FAIL 没有整句重复（≥24 字的片段不得出现 3 次）  1 处，最多的一段重复 3 次：。 2025年某市低空经济全产业链产值412.6亿元，比20…
```

只红该红的那一条，是这套东西里最要紧的性质。一份有毛病的报告如果连带十条不相干的判据一起报红，就没人会去看那份报告了。每个坏样本都是现派生的，每次只改一处，派生完立刻核对确实只报出那一条。

## 规矩清单

```
$ py report_check.py --list-rules
公文专属  开篇有「摘要」章（照范本格式时跳过）
公文专属  有「数据来源」章且非空（照范本格式时跳过）
公文专属  一级标题用「一、二、三、」（照范本格式时跳过）
公文专属  二级标题用「（一）（二）」且不止一个（照范本格式时跳过）
通用      正文是段落（≥25 段）
通用      不用「-」项目符号（≤3 行）
通用      正文没有加粗
通用      没有 emoji
公文专属  至少有 2 张表格（照范本格式时跳过）
通用      不引用「图 N」（本报告没有配图）
公文专属  建议用「一是……二是……三是……」 （照范本格式时跳过）
公文专属  有归类归纳（「划分为三类：……分别为……」）（照范本格式时跳过）
通用      没有「综上所述」这类作文腔
通用      没有自我免责段（面板底部已有提醒）
公文专属  正文 8000-16000 字（照范本格式时跳过）
通用      没有整句重复（≥24 字的片段不得出现 3 次）
```

这一屏不是文档抄的，是 `rules.RULES` 这张表渲染出来的。规则名、是否公文专属、清单本身，三者同一处定义。

每条判据后面跟着实际量到的数：`51 段`、`9814 字`、`2 张表，表号 3 处`。判据判的是什么，看输出就知道，不用翻代码。

最后那一节是机器判不了、列出来给人看的：位次表述有没有出处、归类归纳出现在哪、参考资料里哪些书名号对不上。这一节不参与打分，也不拦退出码。

## 两条入口

### 零密钥：`--print-system`

检查这一半完全不需要模型。要生成，也不必配密钥：

```bash
py report_check.py --print-system --topic "某市低空经济产业" --to "某某市科学技术局" > system.md
```

把 `system.md` 交给任何一个能写字的模型照它写，写完了拿回来检查：

```bash
py report_check.py 报告.md
```

`--print-system` 打到 stdout，`fmt: gw|exemplar` 这行打到 stderr，重定向出来是干净的规范。这条路永远可用。

旁边放一份 `<同名>_refs.md` 做参考资料，检查时会自动读，书名号里的文件名是不是编的就靠它核。生成的时候会自动落一份。

### 直连生成：`--gen`

```bash
export DEEPSEEK_API_KEY=...             # 或者 cp .env.example .env 再填
py report_check.py --gen --topic "某市低空经济产业" --to "某某市科学技术局"
```

OpenAI 兼容接口，DeepSeek、硅基流动、本地 Ollama 都能接，设 `DEEPSEEK_BASE_URL` 指过去即可。

没配密钥时明确报错退出，退出码 2，并把零密钥那条列在前面。没配密钥时不会发起任何请求，不是发出去等 401。上游出错、连不上、被中断，一律不落盘。密钥一律从环境变量读，不留任何默认值。

## Claude Skill

仓库自带一个 Claude Skill，在 [.claude/skills/gongwen-report/SKILL.md](.claude/skills/gongwen-report/SKILL.md)。用 Claude Code 打开这个目录就自动生效，不用安装。

它管的是**流程**，不是判据：告诉模型先 `--print-system` 把规范取出来，照着写，写完必须跑 `report_check.py`，报红的逐条改到全绿；同时钉住几条纪律——不许为了过检放宽判据、不许在没有资料时凭印象编数据或政策文号、不许把范本的内容当成报告内容抄。

规范本身不在 Skill 里另写一份，取的就是 `gongwen/templates/` 里那一份，所以 Skill 和命令行永远不会各说各话。

不用 Claude Code 也一样：`--print-system` 打到 stdout 的那份规范，交给任何能写字的模型都成立。

## 和原来相比，生成变了什么

- **不再自主联网检索。** 参考资料由 `--refs <file>` 或 `--docs <file>` 传进来。检索那一半整段剪掉了，换来的是纯函数、可复现、不需要任何外部服务。代价是它不会自己去查了，得你把资料给它。
- **骨架只有一套。** 命中「按上传文档的格式写」且真从文档里抽出了骨架才换范本骨架；抽不出骨架就退回公文骨架。命中了但抽不出东西不能交出一份没有骨架的报告。
- **范本身份要守住。** 上传的范本是素材，不是内容模板。报告和范本逐字重合 ≥24 字的片段会被列出来，对策句的着力点重合不算抄，整句照搬才算。

## 证伪

每一层都有把自己改坏的入口：

```bash
py report_check.py --selftest            # 36 项：判据本身在不在判、规则表是不是唯一来源
py fixtures/derive.py                    # 三个「只差一处」的坏样本，逐份核对只报出那一条
py tests/test_print.py                   # 五种版式改坏，每种必须由指定那一条报红
py tests/run_all.py                      # 一次跑完全部
```

版式那一层开 headless 浏览器量真页面，再印 PDF 回读字号和边距。

| `--break` | 改坏的是 | 谁该报红 |
|---|---|---|
| `indent` | 缩进按元素自身字号算 | 层次序数同起排 |
| `sign` | 落款日期不与署名右移二字 | 落款右空 |
| `font` | 落款拿不到正文字号 | 落款字号与正文一致 |
| `table` | 表格掉回四号 | 正文与表格统一 3 号 |
| `paper` | `@page` 四边边距错 | 版心边距 |

只判「有红」不够。改坏了缩进却让「落款字号」报红，说明这两条判据接错了线，那种红没有任何意义。

### 退出码

```
0   全过
1   有失败项——报告有毛病，去改报告
2   用法错，或环境缺东西
```

「我没跑起来」不能混进「报告不合格」。少了 Edge、少了 pypdf，都必须响亮地说「这一层没验」并给退出码 2，而不是安静地变绿。

想自己看一眼版式：

```bash
py preview/build.py fixtures/print_sample.md --png 版式.png
py preview/build.py fixtures/print_sample.md --png 坏的.png --break indent   # 故意改坏，对着看
py preview/build.py --print-frontier                        # 这台机器上找不找得到 Edge
```

README 顶上那张图就是第一条命令出的。`--png` 会藏掉页面顶部那行说明，截出来的只有文档本身。

Markdown 渲染用 marked，安全过滤用 DOMPurify，两个库离线 vendored 在 `preview/vendor/`，不走 CDN。

### 版头、版记和落款（`preview/build.py`）

正文（标题、主送机关、正文）是 Markdown 里写的；版头、版记、落款**不写进 Markdown**，
由 `preview/build.py` 按 GB/T 9704 的 7.2 / 7.4 / 7.3.5.2 排在正文前后。这些字段是发文
机关在正式发文时赋上的，所以**没给的整行不画**，绝不替它编：

```bash
py preview/build.py fixtures/print_sample.md --png 版式.png \
  --banner "某某市科学技术委员会文件" --doc-no "某科发〔2026〕1号" --signer "张三" \
  --copy-no "0001" --secret "秘密★3年" --urgency "特急" \
  --cc "某某市发展和改革委员会" --printer "某某市科学技术委员会办公室" \
  --print-date "2026年10月10日"
```

| 块 | 内容 | 标志 |
|---|---|---|
| 版头 | 份号 / 密级和保密期限 / 紧急程度（3 号黑体顶格）、发文机关标志（居中**红色**大字，即「红头」）、发文字号、签发人、红色分隔线 | `--copy-no --secret --urgency --banner --doc-no --signer` |
| 落款 | 发文机关署名、成文日期（不加盖印章：署名右空二字、日期首字右移二字） | `--org --date` |
| 版记 | 抄送机关、印发机关和印发日期，首末粗线中间细线 | `--cc --printer --print-date` |

落款走「不加盖印章」那条（标准 7.3.5.2），和导出 Word 那一路（原 ai智能体 的
`report_docx.py`）同一个口径。版记不复现「排在最后一面版心底端」——浏览器打印做不了
把一块内容锚到页面底部的定位，这里是接在落款后面另起一段排，内容和线形一致。

## 已知边界

- **「照着我上传的报告的格式写」不认。** 认的是「这篇文章、这份文档、这个附件」那一组指代，「上传的报告」不在里面。判不准就不认。
- **「以附件为准」不认。** 可能指数据也可能指格式，判不准就不认。
- **否定词隔了 9 个字以上，闸门仍会开。** 比如「按照我上传文档的格式写，但那份文档只是素材」。这是窗口宽度 8 个字的直接后果，已知边界，不是意外。
- **带上传标记时体例提示里的「结尾有」不列。** 分隔行挤掉了尾部四分之一。骨架里仍然有那一行，换骨架不受影响。
- **上传 `.md` 抽不出体例。** 抽取认的是 PDF/Word 抠出来的裸标题，Markdown 的 `## 一、引言` 认不出来。要它认就把上传文档存成 docx/pdf。
- **`--gen` 不再自主联网。**

## 仓库里没有什么

- 没有任何密钥，也没有默认值。`test_no_secrets.py` 每次都扫一遍全仓。
- 没有真实生成的报告。`fixtures/` 里的样本是中性抽象样本，无地域、无单位、数据是演示用的。
- 没有 PPT、没有向量库、没有国标 PDF、没有单位资料。

## 出处与许可

规则清单、版面参数、判据阈值全部来自 GB/T 9704—2012《党政机关公文格式》以及在真实报告上跑出来的结果。判据是搬过来的，不是重新设计的，阈值一个都没放宽。
